# Makoto Chat Extension — вкладки чата для Minecraft

Клиентский мод для **Minecraft 26.2 и 26.3** (Fabric Loader 0.19.5, Java 25).
С одного исходника собираются две версии мода — по одной на каждую версию игры.

## Что делает

Разбивает серверный чат на вкладки:

| Вкладка | Что туда попадает |
|---------|-------------------|
| **Общий** | Всё, что не опознано как специфичное: обычные реплики, серверные объявления |
| **ЛС** | Личные сообщения всех видов (`/w`, `/msg`, `/tell`, `/r`) — в одной вкладке |
| **Город** | Чат города сервера: сообщения с префиксом `?` и строки с серверным маркером |
| **CoreProtect** | Вывод команд CoreProtect, откаты, отказы сервера |
| **Глобальный** | Чат глобалки (`!`) и сообщения о входе/выходе игроков |
| **Локальный** | Локальный чат: строка вида `[метка] Ник [$] > текст` |
| **Тикеты** | Панели и уведомления тикетов (`MT #NNNNN`, `MT У тебя есть активные тикеты…`) |

Главное свойство: **вкладки обновляются независимо от активной**. Если открыта
«Город», а тебе пришло личное сообщение — оно попадёт в «ЛС» и будет там,
когда переключишься. Ничего не проматывается.

Полоска вкладок видна только пока виден сам чат: она гаснет вместе с ним по той
же формуле затухания, что и ванильный чат (10 секунд после последнего сообщения).
При открытии чата (клавиша `T`) вкладки показываются полностью и в них можно
кликать; когда чат закрыт, вкладки живут в HUD и переключаются клавишами.

## Управление

Клавиши назначаются в стандартных настройках управления, категория **Makoto Chat Extension**:

- `Следующая вкладка чата` — переключение вперёд
- `Предыдущая вкладка чата` — переключение назад
- `Показать/скрыть полоску вкладок` — показывать/скрывать панель вкладок

Команды (работают без назначения клавиш):

```
/chattabs              — сводка: активная вкладка и количество сообщений в каждой
/chattabs next|prev    — переключить вкладку
/chattabs tab global|direct|city|core_protect
/chattabs clear active|all
/chattabs overlay      — показать/скрыть полоску вкладок
```

## Меню настроек (🔧)

Вкладка 🔧 открывает меню, где каждая вкладка — отдельная строка:

- **клик по боксу с галочкой** справа — включить или выключить вкладку;
- **перетаскивание строки** (зажать и вести вверх или вниз) — поменять её место
  в полоске под чатом; строка едет за курсором, а место вставки подсвечивается
  жёлтой полосой;
- клик по названию без перетаскивания — то же, что клик по боксу: переключает.

Порядок хранится списком в `TabSettings`, а не множеством: множество не помнит
порядок. Полоска вкладок, меню и переключение по кругу читают один и тот же
список, поэтому они всегда совпадают. Служебная 🔧 всегда последняя и не
перетаскивается — иначе её можно было бы убрать из привычного места и потерять
доступ к меню. Выключенные вкладки в списке остаются: их надо куда-то вернуть.

## Установка

1. Положи в папку `mods` **тот** файл, который подходит твоей версии игры:
   - Minecraft 26.2 → `makoto-chat-extension-<версия>+26.2.jar`
   - Minecraft 26.3 → `makoto-chat-extension-<версия>+26.3.jar`
2. Установи Fabric API для своей версии игры (`0.161.0+26.2` или `0.163.0+26.3`)
3. Fabric Loader `0.19.5` или новее

Файлы для разных версий игры не взаимозаменяемы: в манифесте мода прописан
диапазон `~26.2` или `~26.3`, поэтому мод для 26.2 на 26.3 просто не загрузится.

## Сборка

Версия игры выбирается ключом `-Pmc`. Свойства каждой версии лежат в
`targets/<версия>.properties`, поэтому исходный код общий:

```bash
export JAVA_HOME=/usr/lib/jvm/java-25-openjdk-amd64
export PATH=$JAVA_HOME/bin:$PATH

./gradlew build -Pmc=26.2      # Minecraft 26.2
./gradlew build -Pmc=26.3      # Minecraft 26.3
```

Готовые файлы (каждая версия — в своей папке, чтобы не смешивались):

```
build/26.2/libs/makoto-chat-extension-<версия>+26.2.jar
build/26.3/libs/makoto-chat-extension-<версия>+26.3.jar
```

Версия мода — одна на все цели и задаётся в `gradle.properties` (`mod_version`).
Правило: при каждой сборке прибавляем единицу к последнему числу
(`1.0.1` → `1.0.2`). Суффикс версии игры подставляется из цели сборки.

Чтобы добавить поддержку новой версии игры, положи `targets/<версия>.properties`
с её номерами — править код при этом не нужно, пока API не разошлись.

## Как устроено

```
ChatTabsClient          точка входа: подписка на события, бинды
ChatRouter              приём сообщений и раскладка по вкладкам
MessageClassifier       эвристика: текст -> канал
FormattingCodes         снятие §-кодов и hex перед классификацией
TabStore                независимое хранилище вкладок (кольцевой буфер 500)
ChatTabFilter           раздаёт ванильный рендер только активной вкладке
TabOverlay              полоска вкладок в HUD и в открытом чате
TabSettings             какие вкладки показывать и в каком порядке; 🔧 открывает меню
TabSettingsScreen       меню настроек: вкладка, бокс справа, перетаскивание строк
ChatTabsCommands        /chattabs — переключение и отладка
```

Разделение видимого чата сделано через
`ChatComponent#setVisibleMessageFilter` — ванильный рендер сам спрашивает,
что показывать, поэтому переключение вкладок мгновенное и не требует
перерисовки списка. **Рендер ванильного чата не переопределяется**: строки
рисует сам Minecraft, мод только решает, какие из них видны.

### Почему глубина истории — 100 сообщений

Это потолок самого ванильного чата, а не настройка мода. Проверено по
байткоду:

- `ChatComponent#allMessages` обрезается до 100 сообщений внутри
  `addMessage` — **до** вызова `setVisibleMessageFilter`, поэтому фильтр не
  может ни удержать старую строку, ни подсунуть новую;
- `trimmedMessages` (то, что реально рисуется) собирается только из
  `allMessages`, собственного списка у чата нет;
- оба поля `private` — расширить историю штатно нельзя.

Снять предел можно было бы миксином или собственным отрисовщиком строк.
Миксины запрещены по требованию, а собственный рендер пробовался и сломал
геометрию чата — откачено.

Что из этого следует на практике:

- глубина видимой истории общая на все вкладки: 100 последних сообщений;
- счётчики непрочитанного живут в `TabStore` (500 на вкладку) и этому
  ограничению не подчиняются — вкладка может «накопить» больше, чем видно.

### Совместимость версий игры

Код общий для 26.2 и 26.3, потому что расхождений в использованных API почти
нет. Единственное найденное: константа типа клавиатуры в
`InputConstants.Type` переименована (`KEYSYM` в 26.2 → `KEYBOARD` в 26.3).
Обошли не проверкой версии, а выбором перегрузки конструктора
`KeyMapping(имя, код, категория)` — она сама подставляет нужный тип в каждой
версии (сверено по байткоду `KeyMapping.<init>`).

Прочие замечания по 26.x:

- Маппинги только Mojang (Yarn больше не поддерживается ядром Fabric)
- Рендер GUI идёт через `extractRenderState` / `GuiGraphicsExtractor`;
  текст рисуется методом `text(...)`, а не `drawString(...)`
- Клавиши вводятся через `KeyEvent`, а не старым `int keyCode`
- Модуля `fabric-keybinding-api-v1` больше нет: `KeyMapping` регистрирует
  себя сам при создании
- Ванильный чат живёт в `Hud`, а не в `Gui`

## Проверка

Логика проверяется на **собранном** моде, а не на исходниках: стенды грузят
готовый jar через `URLClassLoader` на classpath клиента и вызывают методы
напрямую. То есть проверяется тот байткод, который получит игрок.

```bash
verify/run.sh 26.2
verify/run.sh 26.3
```

Стенды: `VerifyLayout` (геометрия полоски и затухание вместе с чатом),
`VerifyTabOrder` (порядок и видимость вкладок), `VerifyServerFormat`
(разбор форматов серверного чата), `VerifyRouting` (маршрутизация сообщений
по каналам, цветовые коды, независимость вкладок, пределы хранилища).

## Ограничения

Классификация эвристическая: формат сообщений задаёт серверный плагин, а
универсального протокола «это личное сообщение» в Minecraft нет. Если плагин
на сервере пишет ЛС неожиданно, добавь маркер в `MessageClassifier`.

Классификатор не различает ЛС и городской чат по содержанию — оба приходят
формой «ник → ник». Разделение идёт по маркерам: свой ввод с «?» считается
городским, всё остальное с формой «ник → ник» — личным сообщением.
